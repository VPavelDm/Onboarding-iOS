# Keyword Research (SERP-grounded)

Exact search volumes need paid tools you probably don't have. What you CAN observe for
free is more decision-relevant anyway: **who currently ranks for a query** (SERP
composition) tells you whether a small new site can win it.

## Method

1. **Enumerate candidate queries** from three sources: the listing copy (what the app
   says it does), competitor app names/subtitles surfaced by the store's "you might also
   like", and the questions the app answers (each feature = someone's search query).
2. **Run live searches** (WebSearch) for each candidate cluster. Classify each SERP:
   - *Big-brand wall* (Duolingo/Notion/etc. + major listicles) → long-term target only
   - *Listicle-dominated* → win by getting INTO those listicles (note for NEXT-STEPS.md),
     plus own a comparison page for the query
   - *Weak/fragmented results* (forums, thin pages, old blogs) → winnable now
3. **Find the wedge**: the intersection of (winnable now) × (high purchase intent) ×
   (uniquely matches this product). Every product has one — the feature competitors treat
   as a checkbox but this app treats as the hero. The wedge cluster gets the most
   dedicated content and the brand association. Ranking there first builds the domain
   authority that later lets broader pages compete.
4. **Map keywords to pages**: commercial/head terms → index page (title, H1, hero copy);
   each long-tail question cluster → exactly one guide page that owns it. One page per
   cluster — two pages targeting the same query cannibalize each other.

## Intent classes and what converts

| Intent | Example shape | Converts? | Placement |
|---|---|---|---|
| Commercial ("X app") | "german vocabulary app" | Highest | index page |
| Comparison ("best app for X") | "best app to learn german" | High | dedicated comparison guide — capture the intent yourself |
| Question ("how to X") | "how to remember der die das" | Medium-high | guide: answer + product integration |
| Informational broad | "german language" | Low | ignore |

## Deliverable: keyword-research.md in the site dir

Include: primary keyword table (keyword, intent, why it converts), long-tail → guide-page
mapping table, the wedge and why it's defensible, competitor apps seen in SERPs, and a
note that volumes are inferred from SERP composition, dated (SERPs change).

## The comparison-page rule

Always create a "best app for {category}" guide. When someone asks an LLM for an app
recommendation, this is the page it fetches. Structure it as an honest buyer's checklist
(what any good app in the category must do), a fair comparison table including real
competitors with their genuine strengths, and the product's position argued from the
checklist. Honesty is load-bearing: LLMs and readers both discount pure advertorial.
